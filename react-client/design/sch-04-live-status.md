# SCH-04 음성 일정 대화의 처리 상태

- 범위: 기존 `VoiceScheduleDialog`의 상태·시간 안내. 2026-10-26 사용자 요청(처리 중인지, 얼마나 기다렸는지 표시)에 따른 작은 보완이며 새 화면·API·예상 완료 시간은 추가하지 않는다.
- 기준: `design/README.md`, 기존 Screen 타입 스타일과 음성 대화 클래스·토큰을 그대로 쓴다.

## 표시와 전환

| 상태 | 상단 상태 | 시간·도움말 |
| --- | --- | --- |
| 연결 준비 | 연결하고 있어요 | 기존 연결 흐름 유지 |
| 대화 중 | 듣고 있어요 | 상단 제목 영역에 `대화 남은 시간 1:03`처럼 세션 종료까지 남은 시간을 명시 |
| `PROCESSING` | 일정 확인 중 | `N초 경과`를 함께 표시. 이 브라우저가 이번 처리 상태를 처음 확인한 때부터 세며 같은 상태의 반복 조회로 초기화하지 않음 |
| 처리 15초 이상 | 일정 확인 중 | `확인에 시간이 걸리고 있어요. 잠시만 기다려 주세요.`를 조건부 표시. 완료 예상·퍼센트·네트워크 제한 시간을 약속하지 않음 |
| `AWAITING_CONFIRMATION` | 동의를 기다려요 · 아직 저장 안 됨 | 서버의 확인 메시지를 표시하고, 없으면 기존 확인·수정 안내 유지 |
| `WAITING_FOR_DETAILS` | 약 이름을 기다려요 / 추가 정보가 필요해요 | 서버의 추가 정보 메시지를 표시. 첫 요청을 기다리는 `request` 상태는 기존 입력 안내 사용 |
| 완료·오류·시간 초과·사용자 종료 | 기존 완료·실패 안내 | 처리 경과 시간을 지움. 기존 마이크 정리·확인 후 저장·완료 안내 뒤 닫힘 유지 |

- 완료 시에는 기존 `Progress.message`를 안내에 표시한다. 한 약 저장·그만 먹기·삭제도 같은 규칙을 쓰고, 메시지가 없을 때는 기존 일정 상세 수정 안내를 유지한다.
- “내 약 전부”는 선택 프로필의 등록 약 전체를 개수 제한 없이 함께 제안하고, 확인 후 저장한다. 서버 메시지에 약 이름과 실제 개수를 표시한다. 프론트는 메시지에서 개수를 추출하지 않으며 기존 `savedSchedule`·`completedOperation`의 대표 첫 일정 카드만 표시한다. 완료 콜백의 기존 전체 달력 재조회로 저장한 일정 전체를 확인하고, `일정 상세`는 카드의 대표 일정만 연다. 공개 API 필드·DB·별도 일괄 목록 UI를 추가하지 않는다.
- 처리 경과 시간과 대화 남은 시간은 서로 다른 값이다. 처리 경과는 최초 관측 시각을 쓰므로 실제 서버 작업 시작부터의 전체 시간이라고 표현하지 않는다.
- 제목·상태·대화 남은 시간을 같은 제목 영역 안에 두어 좁은 창에 별도 고정 폭 열을 늘리지 않는다.
- 초 단위 숫자는 `timer`와 `aria-live="off"`로 표시하여 매초 상태 알림을 반복하지 않는다. 상태 자체와 기존 대화 알림은 유지한다.
- 닫기·대화 끝내기·Esc·다시 시작·일정 상세의 행동은 바꾸지 않는다.

## 검증 범위

- 코드 검증: 반복 처리 조회, 상태 전환, 완료·종료 뒤 늦은 응답에 대한 회귀 검사와 프론트 lint/build.
- 실제 캡처·마이크·음성 왕복·배포 화면 검토: 부모 작업에서 배포 후 확인. 이 정의만으로 확인 완료로 보지 않는다.
