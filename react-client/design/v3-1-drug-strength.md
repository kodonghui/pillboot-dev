# v3 1차 · 기본 이름·함량 표시와 '함량 다름' 후보(TASK-007)

- 범위: MED-01 약 목록, MED-03 이름 검색 결과, MED-04 약 상세, IMG-04 처방전 찾은 약 확인. 새 화면은 없고 기존 화면의 약 이름 칸과 후보 카드만 바꿈.
- 추적: V3-DRUG-004(기본 이름·함량 나눠 보여 주기), V3-REG-001(함량을 뗀 이름으로 검색), V3-REG-002(함량 다름 후보, REG-003 변경), V3-FL-18, DEC-006.
- API: `docs/06-api/openapi-v3.yaml`의 `baseName`·`strengthText`(DrugSearchResponse·DrugInfoResponse·MyDrugListResponse·PhotoCandidate), `strengthMatch`(MATCH·DIFFERENT·UNKNOWN), `PhotoDrugGroup.autoSelectItemSeq`. 새 API 없음.
- 목업: `design/mockups/v3-1/drug-strength/`(A안 `*-a.html`, B안 `*-b.html`, 캡처 `captures/*-360.png`·`*-1280.png`). 실제 화면을 가짜 API로 띄우고 바뀐 부분만 얹은 정적 파일이며 데이터는 모두 예시임.
- 상태: A안으로 정함(DEC-020, 2026-11-02 PM "1A 2A 3A 4A 5A 6A"). 구현은 TASK-008. B안 목업·캡처는 비교 기록으로 남김.

## 후보

| 안 | 이름 칸 | 함량 다름 표시 | 장단점 |
| --- | --- | --- | --- |
| A | 기본 이름(굵게) + 함량을 회색 배지로 | `함량 일치`(초록 배지)·`함량 다름`(노랑 배지) 짧은 배지 | 목록에서 함량이 눈에 잘 띔. 무엇과 다른지는 배지만으로 알 수 없음 |
| B | 기본 이름(굵게) + 함량을 같은 줄 보통 굵기 글자로 | `함량 다름 · 처방전 0.25mg, 이 약 0.5밀리그램`처럼 비교한 두 값을 한 줄로 | 왜 다른지 바로 보임. 줄이 길어 360 폭에서 두 줄이 될 수 있음 |

- 두 안 모두 `함량 일치` 배지는 같고, `확인 불가`(UNKNOWN)는 표시하지 않음(근거 없는 경고를 늘리지 않음).

## 표시와 전환

| 화면 | 응답 | 보여 주는 것 |
| --- | --- | --- |
| MED-01·MED-04 | `baseName`·`strengthText`가 있음 | 기본 이름과 함량을 나눠 보여 줌. MED-04 제목 아래에 `품목명 …` 원문 한 줄을 더함 |
| MED-01·MED-04 | `strengthText`가 null(함량 없음·직접 입력) | 지금처럼 이름 하나만 보여 줌 |
| MED-01·MED-04 | `baseName`이 null(옛 응답·채우기 전 행) | 지금처럼 `name`(품목명)을 그대로 보여 줌 |
| MED-03 | 검색어에 함량이 있음 | 결과 제목 아래 `함량이 맞는 약을 맨 위에 두었어요. 함량이 다른 약도 고를 수 있어요.` 후보마다 MATCH·DIFFERENT 표시 |
| MED-03 | 검색어에 함량이 없음(모두 UNKNOWN) | 정렬 안내·상태 표시 없음. 지금 화면과 같음 |
| IMG-04 | `autoSelectItemSeq`가 있음 | 그 후보를 미리 고른 상태로 보여 줌. 후보 목록 위에 `처방전 함량과 맞는 약이 하나라 미리 골라 뒀어요. 맞는지 확인해 주세요.` 사용자가 다른 후보나 `이 중에 없음`으로 바꾸면 이 줄은 내림 |
| IMG-04 | `autoSelectItemSeq`가 없음, 판독 이름에 함량 없음 | 아무것도 미리 고르지 않음. 아직 고르지 않은 동안 `처방전에서 함량을 읽지 못해 미리 고르지 않았어요. 직접 골라 주세요.` 판독 함량은 API에 없으므로, 함량이 있는 후보까지 모두 UNKNOWN이면 판독 이름에 함량이 없던 것으로 봄. 후보 모두 함량이 없으면 어느 쪽 탓인지 알 수 없어 안내하지 않음 |
| IMG-04 | `autoSelectItemSeq`가 없음, MATCH가 둘 이상이거나 이미 등록됨 | 아무것도 미리 고르지 않음. 미리 고름 안내 줄도 없음 |
| IMG-04 | 첫 안내 문장 | `아무것도 미리 골라 두지 않아요` 문장을 `이름마다 사진에서 읽은 이름과 공식 이름을 비교해 주세요. 함량까지 맞는 약이 하나뿐이면 미리 골라 두었고, 바꿀 수 있어요.`로 바꿈(DEC-006) |

- 미리 고른 후보도 저장은 사용자가 `N개 저장`을 눌러야 함. 미리 고름은 사용자가 다른 후보나 `이 중에 없음`으로 바꿀 수 있음.
- `함량 다름` 후보도 목록에 남기고 고를 수 있음. 다른 후보를 고를 때 막거나 다시 묻지 않음.
- 함량 표시는 서버가 준 `strengthText` 원문을 그대로 씀. 화면에서 단위를 바꾸거나 계산하지 않음. B안 비교 줄의 앞 값은 판독 이름·검색어에서 서버가 읽은 함량을 쓰며, 그 값을 주는 칸이 지금 API에 없으면 구현 전에 차이를 보고함(아래 확인할 것).
- 상태는 색만으로 구분하지 않고 아이콘과 글자를 함께 씀.

## 확인할 것

- B안을 고르면 비교 줄의 '처방전·검색어 쪽 함량' 값이 필요함. 지금 `openapi-v3.yaml`에는 그 칸이 없음(`readName` 원문만 있음). B안이면 서버 칸 추가 또는 화면에서 `readName`을 보여 주는 방식 중 하나를 정해야 함. A안은 지금 API로 충분함. → A안으로 정해 해당 없음(DEC-020).
