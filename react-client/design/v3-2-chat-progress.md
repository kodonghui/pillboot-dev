## 단계 이름

| 서버 `stage` | A안·B안 지금 단계 | B안 지나온 단계 |
| --- | --- | --- |
| `UNDERSTANDING` | 질문 살펴보는 중 | 질문 살펴보기 |
| `FINDING_DRUG` | 약 찾는 중 | 약 찾기 |
| `CHECKING` | 공식 자료·금기 확인하는 중 | 공식 자료·금기 확인 |
| `WRITING` | 답 정리하는 중 | 답 정리 |
| 아직 못 받음·모르는 값 | 답변 만드는 중(1차와 같음) | 목록 없이 `답변 만드는 중` 한 줄 |

- 질문에 따라 건너뛰는 단계가 있음: 기록 질문은 `질문 살펴보기 → 답 정리`, 막힌 질문은 `질문 살펴보기`뿐(곧 안내로 바뀜), 공식 자료가 없으면 `답 정리` 없이 끝남.

## 표시와 전환

| 시간·상태 | 표시 |
| --- | --- |
| 요청 뒤 2초 전 | 1차와 같이 `답변을 만드는 중…`만. 단계는 받아 두되 보이지 않음(빨리 끝나는 답에서 깜빡이지 않게) |
| 2초부터 | 마지막으로 받은 단계 이름 + `N초`. 초는 요청을 보낸 때부터 셈(단계가 바뀌어도 0으로 돌아가지 않음) |
| 단계가 바뀜 | A: 글만 바뀜. B: 지금 줄이 체크로 바뀌고 새 줄이 아래에 붙음. 맨 아래를 보고 있었으면 따라 내려감(1차 규칙) |
| 15초부터 | 1차와 같은 노랑 안내 `평소보다 오래 걸리고 있어요. 이 화면에서 그대로 기다려 주세요.` |
| `result` 받음 | 표시를 지우고 답(또는 막힌 질문 안내)을 기존처럼 보여 줌 |
| `error` 받음 | 기존 JSON 오류와 같게 처리: 503 + 질문 ID → 「다시 보내기」, 400·503 → 입력창에 질문을 돌려놓음, 409 → 대화를 다시 불러옴 |
| 연결이 끊김·90초 넘음·`result` 없이 닫힘 | 기존 CHT-02-11과 같게 상담 기록으로 저장 여부를 확인함(서버는 끝까지 답을 만들어 저장함) |
| 화면을 떠남 | 요청을 끊고 타이머를 지움. 서버는 답을 저장하고, 다시 들어오면 상담 기록에 보임 |

- 완료 예상 시간·퍼센트·남은 단계 수는 보이지 않음.
- 읽어 주기: 말풍선 둘레 `role="status"`가 단계 이름이 바뀔 때만 읽음. 초 숫자는 `role="timer"`·`aria-live="off"`(1차 `WaitSeconds`). B안의 체크 아이콘은 `aria-hidden`이고, 지나온 줄은 글자로 읽힘.
- 요청은 `fetch`로 보내고 응답을 조금씩 읽음(`EventSource`는 로그인 헤더를 못 붙임). 401은 axios와 같이 로그인 만료로 처리함.
