# DEC-034 웹 버그·UX 다듬기(본선 전)

- 범위: MEM-01 시작 화면, SCH-04 음성 대화 실패 상태, SCH-01 복용 달력(구슬 안내·약별 복용 기간), 같은 약을 다시 넣을 때의 안내(MED-03·IMG-04·IMG-05·SCH-03), CHT-02 대화방 입력창과 빈 대화 안내, 영상 흐름의 이음(MED-01). 새 주소·새 API·SQL은 없음.
- 왜: DEC-034, PM "버그와 UX도 고쳐야 한다."(2026-11-04 밤 Claude Code 세션). 할 일은 PM이 준 프롬프트 '버그·UX(DEC-034)'(2026-11-04 프로젝트 대화)에 있음.
- 추적: `docs/13-presentation/2026-11-04-next-session-prompt.md` §8-1~5, V3-REQ-50, `cmn-04-changelog.md`, `sch-04-live-status.md`.
- API: 기존만 씀. `GET /api/profiles/{profileId}/drugs`(`itemSeq`·`startDate`·`endDate`·`doseTimes`), `POST /api/profiles/{profileId}/chat-sessions`(기존 `createChatSession`).
- 목업: 따로 만들지 않음. 기존 카드·배지·글자 스타일을 그대로 쓰고 구현 캡처로 확인함. 문구와 자리는 CT가 정했으며 PM 캡처 확인은 배포 뒤 받음.

## 1. MEM-01 '업데이트 기록' 빼고 강점 드러내기

- PM 프롬프트 "'업데이트 기록'을 로그인 전 화면에서 뺌(로그인 옆 버튼·팝업으로 둘지는 화면정의서에서 정함)"에 따라 **본문 묶음을 빼고, 바닥 출처 줄에 작은 링크만 둠**.
- 머리말 버튼·팝업으로 두지 않는 까닭: 좁은 화면 머리말은 `로그인`·`시작하기`만으로 이미 한 줄이 참. 업데이트 기록은 처음 온 사람의 행동이 아니므로 첫 화면의 시선을 받지 않게 함.

| 자리 | 내용 |
| --- | --- |
| 위치 | '필받음으로 할 수 있는 일' 아래, 맺음 안내 위(업데이트 기록이 있던 자리) |
| 제목 | `믿고 챙길 수 있게`(screen-section, h2) |
| 칸 1 | 아이콘 `bell`, 제목 `복약 알림은 크롬으로 받아요`, 글 `알림을 켜 두면 복용 시간마다 크롬으로 알려 드려요. 부모님 약을 등록해도 알림은 로그인한 나에게 와요.` |
| 칸 2 | 아이콘 `book`, 제목 `공공데이터로 확인한 약 정보`, 글 `약 정보와 같이 먹으면 안 되는 약은 식품의약품안전처 공공데이터로 확인해요. 답할 때는 근거도 함께 보여 드려요.` |
| 넓은 화면 | 두 칸(기능 소개와 같은 위 선·아이콘 모양) |
| 좁은 화면(720px 이하) | 한 칸으로 쌓음 |
| 바닥 출처 줄 | 비로그인 시작 화면에서만 `필받음` 앞에 링크 `업데이트 기록`(CMN-04로, 누르는 범위 높이 44px 이상) |

- 사실 근거: 알림 대상은 로그인한 회원(`MedicationReminderRepository.targets`, 다음 세션 프롬프트 §7). 출처는 기존 바닥 줄 `식품의약품안전처 공공데이터(의약품 허가정보, e약은요, 낱알식별, DUR)`.
- 카톡 복약 알림(DEC-033)이 운영에서 켜지면 칸 1 제목을 다시 봄. 이 화면정의서에서 미리 쓰지 않음.

## 2. SCH-04 마이크를 못 쓸 때 약봉이로 넘기기

| 상태 | 아래 버튼 |
| --- | --- |
| `micDenied`(마이크를 쓸 수 없어요) | `닫기`, `약봉이에게 글로 말하기`(assistive), `다시 시작`(solid) |
| `unavailable`(음성 대화를 이어 갈 수 없어요) | `닫기`, `약봉이에게 글로 말하기`(assistive), `다시 시도`(solid). 음성 기능이 꺼졌을 때도 같은 길이 필요해서 함께 둠 |
| `busy` · `timeout` · 대화 중 · 완료 | 바꾸지 않음 |

- 누르면: 음성 대화 창을 닫고, 달력에서 상세를 연 일정이 있으면 그 사람, 없으면 관리할 사람으로 **관리할 사람을 맞춘 뒤** 새 대화방을 열어 CHT-02로 감(`createChatSession`은 쓰지 않은 빈 방이 있으면 그 방을 다시 줌). 만들기에 실패하면 CHT-01로 감(거기서 다시 시도할 수 있음).
- 맥락: 상세를 연 일정이 있으면 입력창에 그 약 이름과 빈칸 하나를 넣어 둠. 보내지 않음(`question`을 쓰지 않음).
- 입력창 아래 안내(CHT-02 `hint` 자리, 방이 비어 있는 동안만): `말하려던 일정을 글로 써 주세요. 예: 타이레놀 아침 8시 한 알로 바꿔 줘`. 예시는 2026-11-04 운영 서버 시험(TC-165)에서 일정 카드가 나온 말임.
- 버튼을 누르는 동안 두 번 눌리지 않게 잠그고, 마이크를 잡지 않은 상태라 끊을 것은 없음. 좁은 창에서 버튼은 여러 줄로 감(기존 `flex-wrap`).

## 4. SCH-01 약별 복용 기간

- 위치: 달력(과 일정 상세) 아래. 프로필마다 약의 시작일~끝일을 보여 주는 읽기 전용 목록. 새 컴포넌트 `ScheduleHistory`.
- 값: 프로필마다 `GET /api/profiles/{profileId}/drugs`를 부르고 일정이 있는 약만 씀(`hasSchedule`). 달력 범위에 걸리지 않는 지난 일정도 보임. 달력을 다시 불러올 때 함께 다시 부름.
- **이력의 한계**: 약 하나에 일정 하나만 있어(V3-REQ-50) 일정을 바꾸면 앞 기간은 남지 않음. 그래서 제목을 '이력' 대신 `약별 복용 기간`으로 쓰고, 설명에 그 사실을 적음.

| 자리 | 내용 |
| --- | --- |
| 제목 | `약별 복용 기간`(screen-section, h2) |
| 설명 | `지금 일정의 시작일과 끝일이에요. 일정을 바꾸면 바뀐 기간으로 보여요.` |
| 묶음 | 프로필 순서대로. 머리에 `ProfileTag`(프로필 색과 이름). 일정 없는 프로필은 뺌 |
| 한 줄 | 약 이름(`DrugName`) · `2026.10.14 ~ 2026.11.12`(숫자 고른 폭) · 상태 배지. 시작일이 늦은 것부터 |
| 상태 배지 | `먹는 중`(primary) · `시작 전` · `끝남`. 색만으로 구분하지 않고 글자를 씀(`scheduleState`) |
| 누르면 | 그 일정의 일정 상세(SCH-05)를 열고 달을 그 일정에 맞춤(`calendarMonth`). 포커스는 상세로 감(막대를 누를 때와 같음) |
| 좁은 화면(720px 이하) | 이름 → 기간·배지로 두 줄 |

| 상태 | 화면 |
| --- | --- |
| 불러오는 중 | 묶음을 그리지 않음(달력의 빈 달 안내가 있어 자리를 비워 둠). 다시 불러올 때는 앞 값을 그대로 둠 |
| 일정이 하나도 없음 | 묶음 전체를 그리지 않음 |
| 실패 | Notice(negative) `약별 복용 기간을 불러오지 못했어요. 달력의 일정은 그대로 있어요.`와 `다시 시도` |
| 달력을 불러오지 못했을 때 | 함께 숨김 |

## 5. 같은 약을 다시 넣을 때

- 지금: 한 프로필에 같은 약은 하나만 있음(`my_drug` 유일 제약, V3-REQ-50). 화면은 `이미 등록한 약이에요`로 멈추고 다음에 무엇을 할지 말하지 않음.
- 고침: 멈추는 자리마다 **그 약의 일정으로 가는 링크**를 둠. 서버는 바꾸지 않음. 등록 응답·409 규칙도 그대로임.

| 화면 | 자리 | 링크 |
| --- | --- | --- |
| MED-03 이름 검색 | 후보 줄의 `이미 등록한 약이에요` 아래, 고른 약의 안내 Notice | 일정이 있으면 `일정 고치기`(SCH-06), 없으면 `일정 정하기`(SCH-03) |
| IMG-04 처방전·약봉투 후보 | `이미 등록한 약이에요` 옆 | 같음 |
| IMG-05 알약 후보 | `이미 등록한 약이에요` 옆 | 같음 |
| SCH-03 일정 추가 | 이미 일정이 있는 약을 고르면 나오는 주의 Notice | `지금 일정 고치기`(SCH-06) |

- 링크의 `from`은 `drug`임. 저장·취소 뒤 그 약 상세로 돌아감.
- 어느 약인지(`myDrugId`)는 후보 응답에 없어, 그 화면이 `GET .../drugs`를 한 번 불러 `itemSeq`로 찾음. 새 훅 `useMyDrugIndex`. 못 찾거나 실패하면 링크 없이 지금 글만 보임.
- 등록 중 409가 나 이미 등록으로 바뀌면(MED-03) 목록을 다시 불러 링크를 보임.
- 사진 후보 화면에서 링크를 눌러도 임시 결과는 지우지 않음. 뒤로 가면 결과가 그대로 있음.
- CHT-02 등록 카드의 `이미 약목록에 있어요`는 바꾸지 않음. 카드는 대화 안에서 끝나는 흐름이고 일정은 대화로 이어 말할 수 있음.

한 약에 두 일정을 두는 일은 화면으로 풀리지 않음. 스키마 변경 안은 `docs/12-qa/runs/2026-11-05-web-ux-walk.md`의 'PM에게 여쭐 것'에 적음.

## 6. 영상 흐름을 걷고 고친 곳

사진 등록 → 같이 먹어도 되는지 → 일정 → 달력 → 알림을 걸어 보고 고친 곳임. 찾은 근거는 `docs/12-qa/runs/2026-11-05-web-ux-walk.md`에 있음.

| 화면 | 자리 | 내용 |
| --- | --- | --- |
| MED-01 약 저장 직후 | 안내의 버튼 | `일정 추가` 앞에 `같이 먹어도 되는지 묻기`(약봉이로 감)를 더함. 좁으면 아래 줄로 내려감 |
| MED-01 일정 저장 직후 | 새 안내 | 약 목록에서 일정을 넣고 돌아오면 positive 안내 `일정을 저장했어요.`와 `복용 달력 보기`(일정 시작 달로 감). 전에는 아무 말 없이 목록으로 돌아왔음. 다른 곳에서 온 일정 추가는 그 화면이 바뀐 일정을 보여 주므로 그대로임 |
| IMG-04·MED-03 | 저장 줄 안내 | `복용 일정은 저장 후 약 상세에서 등록해 주세요.`를 `복용 일정은 저장한 뒤 약 목록에서 바로 정할 수 있어요.`로 바꿈. 저장하면 약 상세가 아니라 약 목록으로 가기 때문임 |
| IMG-04 | 이름 묶음의 상태 배지 | 고르지 않았고 후보에 이미 등록한 약이 있으면 `아직 고르지 않았어요` 대신 `이미 등록한 약이 있어요`. 고를 일이 없는데 할 일이 남은 것처럼 보였음 |
| MED-03 좁은 화면(720px 이하) | 이미 등록한 후보 줄 | 안내와 `일정 고치기`를 이름 아래 줄로 내림. 한 줄에 두면 약 이름이 세로로 찢어짐 |
| CHT-02 빈 대화 | 안내 아래 | caption `약 이름과 함량까지 적으면 더 정확해요. 예: 노바스크정 5밀리그램이랑 타이레놀정 500밀리그람 같이 먹어도 돼?`. 짧은 이름으로 물으면 제품을 다시 묻는 것을 2026-11-04 스테이지 QA에서 봄 |

## 접근성

- 새 링크·버튼은 글자로 뜻을 전하고 높이 44px 이상임(기존 `mt-btn`). 사진 후보의 링크는 라디오 `label` 밖(이미 등록한 후보는 `label`이 아님)에 있음.
- 약별 복용 기간: h2 → 프로필 이름(목록 이름표) → 목록. 줄은 링크이고 접근 이름에 사람·약·기간이 들어감.
- 구슬 아래 안내는 눈에 보이는 글이며, 구슬의 이름(`aria-label`)은 그대로임.
