# v3 1차 · MED-01 선택 모드와 여러 개 삭제 확인 창(TASK-011)

- 범위: MED-01 약 목록에 선택 모드·고른 수·삭제 확인 창·결과 안내를 더함. 새 화면은 없음. 약 상세의 한 건 삭제는 그대로임.
- 추적: V3-DRUG-003, V3-FL-17, V3-REQ-39·40·77, V3-COMMON-003.
- API: `POST /api/profiles/{profileId}/drugs/bulk-delete` 본문 `{ myDrugIds: [1~50개] }`, 응답 `{ deletedCount }`. 400·401·404는 `openapi-v3.yaml` 그대로이며 404면 아무것도 지워지지 않음.
- API 계약 차이(보고): 프론트 기준 스냅샷 `design/pill-api-docs.json`(v1, 경로 42개)에는 이 경로가 없음. `docs/06-api/openapi-v3.yaml`과 `MyDrugController.deleteMyDrugs`가 서로 맞아 그 둘을 따라 구현함. 같은 스냅샷에 v3의 `OTHER`·함량 필드도 없음. 스냅샷은 v3 백엔드를 띄워 `/v3/api-docs`로 다시 받아야 하며, 이 작업에서는 로컬 백엔드 DB 설정(`.env`)이 없어 받지 못함.
- 목업: `design/mockups/v3-1/bulk-delete/`(`entry-a`·`mode-a`·`entry-b`·`mode-b`, 공통 `confirm`·`done-a`·`stale-a`, 캡처 `captures/`).
- 상태: A안으로 정함(DEC-020, 2026-11-02 PM "1A 2A 3A 4A 5A 6A"). 구현은 TASK-012. B안 목업·캡처는 비교 기록으로 남김.

## 표시와 전환

| 상태 | 화면 | 동작 |
| --- | --- | --- |
| 기본(약 1개 이상) | 지금 목록 + 선택 진입 버튼 | 약이 0개면 선택 진입 버튼을 보이지 않음 |
| 선택 모드, 0개 | 체크 칸이 생기고 `약 등록`·행의 `일정 등록` 버튼을 숨김. 상태 글 `삭제할 약을 골라 주세요`, 삭제 버튼 잠김 | 약 이름은 링크 대신 그 행 고르기로 동작함 |
| 선택 모드, N개 | 고른 행 바탕을 `primary-weak`로, 상태 글 `N개 골랐어요`, `N개 삭제` 활성 | 전체 선택은 모두 고름·모두 풂을 오감 |
| 확인 창 | 제목 `약 N개를 삭제할까요?`, 고른 약 이름 목록, `이 약들의 복약 일정과 알림도 함께 지워져요. 삭제한 뒤에는 되돌릴 수 없어요.`, `취소` · `N개 삭제`(빨강) | 기존 `ConfirmDialog`(Esc·바깥 포커스 가두기) 그대로. 취소하면 고른 상태 유지(V3-FL-17) |
| 삭제 중 | 확인 창의 `N개 삭제` 버튼에 도는 아이콘, 두 버튼 잠금 | 같은 요청을 두 번 보내지 않음 |
| 200 | 확인 창 닫기, 선택 모드 끝, 목록 다시 불러오기. 맨 위 초록 안내 `약 N개를 삭제했어요.` `함께 있던 복약 일정과 알림도 지웠어요.` | N은 응답 `deletedCount` |
| 404 | 확인 창 닫기, 목록 다시 불러오기, 선택 모드는 유지하고 고른 것은 비움. 노랑 안내 `아무것도 삭제하지 않았어요.` `고른 약 중에 이미 삭제된 약이 있었어요. 목록을 다시 불러왔으니 다시 골라 주세요.` | 서버가 아무것도 지우지 않았으므로 '일부 삭제'로 쓰지 않음 |
| 400 | 확인 창 안 오류 줄 `요청을 처리하지 못했어요. 다시 시도해 주세요.`, 고른 상태 유지 | 화면이 1~50개·중복 없음을 지키므로 보통 생기지 않음. 51개 이상은 화면에서 막음(`한 번에 50개까지 지울 수 있어요.`) |
| 401 | 기존 로그인 만료 흐름(`docs/auth-logout.md`) | 그대로 |
| 네트워크 오류 | 확인 창 안 오류 줄 `연결이 끊겨 삭제하지 못했어요. 다시 시도해 주세요.` | 결과를 모르므로 목록을 다시 불러와 맞춤. 받을 때까지 확인 창 두 버튼은 삭제 중 그대로 잠금(이미 지워진 약을 다시 보내지 않게). 다시 받은 목록에서 고른 약이 모두 빠졌으면 서버가 지운 것으로 보고 확인 창을 닫고 완료 안내(`약 N개를 삭제했어요.`)·선택 모드 끔·`선택` 포커스. 남은 약이 있으면 그 약만으로 확인 창을 두고 오류 줄을 보임. 목록도 받지 못하면 확인 창을 닫고 목록 오류 안내에 맡김(고른 것은 둠) |

- 선택 모드에서 관리할 사람을 바꾸면 선택 모드·확인 창·오류를 끄고 고른 것을 비움. 다시 돌아와도 전에 고른 약이 살아나지 않음.
- 고른 수와 상태 글은 `role="status"`로 바뀔 때만 읽힘. 체크 칸은 상자 22px, 누르는 범위 44px.
- 머리 줄 전체 선택 칸은 일부만 고르면 '일부 선택'(indeterminate)으로 보이고, 누르면 모두 고름.
- 51개 이상 고르면 상태 글을 `N개 골랐어요. 한 번에 50개까지 지울 수 있어요.`로 바꾸고 `삭제` 버튼을 잠금.
- 포커스: `선택`을 누르면 전체 선택 칸으로, `취소`·삭제 완료 뒤에는 다시 `선택` 버튼으로, 404 뒤에는 전체 선택 칸으로 옮김(사라진 버튼에 포커스가 남지 않게).
- 삭제 중에는 확인 창을 Esc로도 닫지 않음.
- 360 폭처럼 표가 가로로 밀릴 때 선택 모드 약 칸 글은 체크 칸을 뺀 보이는 폭 안에서 줄바꿈함(`v3-1-drug-strength.md`, BUG-001).

## 검증 범위

- 목업 캡처: 360·1280 폭에서 A·B 선택 전·선택 모드, 공통 확인 창·완료·404 안내를 찍어 봄. 360 폭에서 표는 기존처럼 가로로 밀림.
- 구현(TASK-012): 가짜 API로 1280 폭에서 선택 모드 진입(약 등록·일정 등록 숨김, 전체 선택 칸 포커스), 이름 눌러 고르기, 일부 선택 표시, 확인 창(이름 목록·문구), 삭제 중(두 버튼 잠금·도는 아이콘), 200(완료 안내·목록 갱신·선택 버튼 포커스), 404(노랑 안내·선택 모드 유지·고른 것 비움), 400과 연결 끊김(확인 창 안 오류 줄, 고른 것 유지), 취소(고른 것 유지)를 눌러 봄. 리뷰 반영 뒤: 응답만 잃고 서버가 지운 경우(확인 창 닫힘·완료 안내·선택 모드 끔·`선택` 포커스, 다음에 약을 골라도 확인 창이 저절로 뜨지 않음), 김필받에서 고른 채 엄마로 바꿨다 돌아오기(선택 모드 꺼짐·고른 것 없음)를 확인함. 2차 리뷰 반영 뒤: 연결이 끊긴 뒤 목록을 2.5초 늦게 받게 해 그동안 삭제 버튼이 잠겨 있음, 서버가 지운 경우 완료 안내, 서버가 안 지운 경우 오류 줄과 `1개 삭제` 다시 시도 성공, 목록마저 못 받은 경우 창 닫힘·목록 오류 안내·다시 시도 뒤 확인 창이 저절로 뜨지 않음을 확인함. 360 폭 선택 모드와 고정 바를 봄. `npm run lint`·`npm run build` 통과.
- 아직 안 한 것: 실제 서버 200·404, 키보드만으로 고르기·삭제, 51개 이상 목록, 화면 읽기 프로그램 낭독. 개발 서버 프록시를 거치면 연결 끊김이 5xx로 바뀌어 일반 오류 문구가 보이므로, 연결 끊김 문구는 요청을 브라우저에서 끊어 확인함.
