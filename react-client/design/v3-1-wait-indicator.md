## 표시와 전환

| 시간·상태 | 표시 |
| --- | --- |
| 요청 뒤 2초 전 | 지금처럼 버튼 안 도는 아이콘·기존 기다림 문장만. 경과 초를 보이지 않음(빨리 끝나는 요청에서 깜빡이지 않게) |
| 2초부터 | 단계 이름 + `N초`. 초는 요청을 보낸 때부터 셈 |
| 15초부터 | 위 표시에 `평소보다 오래 걸리고 있어요. 이 화면에서 그대로 기다려 주세요.`를 더함(노랑 글자). 사진은 `사진에 따라 1분 넘게 걸릴 수 있어요.`를 붙임. 답변은 기존 10초 문장 대신 이 문장을 15초에 씀 |
| 성공 | 표시를 지우고 결과를 보여 줌 |
| 실패·시간 초과 | 표시를 지우고 기존 오류 안내·다시 시도 버튼을 그대로 씀 |
| 화면을 떠남·요청 취소 | 타이머를 지움 |

- 단계 이름은 화면이 실제로 아는 것만 씀: 검색은 `공공데이터에서 찾는 중` 하나, 사진은 업로드 진행(axios 업로드 진행 이벤트)이 끝나기 전 `사진 올리는 중`, 끝난 뒤 `사진 읽고 약 찾는 중`, 답변은 `답변 만드는 중` 하나. 서버 내부 단계(판독·조회)를 나눠 보이지 않음.
- 완료 예상 시간·퍼센트는 보이지 않음.
- 초 숫자는 `aria-live="off"`(`timer`)로 두어 매초 읽지 않음. 단계 이름이 바뀔 때와 15초 안내가 생길 때만 `role="status"`로 읽힘.
- 경과 초는 숫자 폭 고정(`tabular-nums`)으로 글자가 흔들리지 않게 함.
- 구현: 초는 기다림 표시 부품이 나타난 때(요청을 보낸 때)부터 0.5초마다 다시 잼(`useElapsedSeconds`). 검색은 요청마다 새로 셈. 검색의 읽어 주는 자리(`role="status"`)는 비어 있어도 늘 둠. 답변의 기존 10초 문장 타이머는 없앰.
- 사진 업로드가 끝났는지는 업로드 진행에서 보낸 양이 전체에 닿을 때로 봄. 전체 크기를 모르면 끝난 것으로 봄.

## 검증 범위

- 목업 캡처: 360·1280 폭에서 검색 A·B(3초), 사진 A·B(12초), 사진 A·B(41초, 오래 걸림), 답변(6초·23초)을 가짜 API가 요청을 붙잡은 실제 기다림 화면 위에 찍어 봄. 답변 360은 마지막 대화 묶음만 자른 캡처임.
- 구현(TASK-016): 가짜 API로 검색 1초(표시 없음)·2.3초(`공공데이터에서 찾는 중 · 2초`)·3.5초 뒤 성공(표시 사라지고 결과 3건)·16초(노랑 안내), 처방전 사진 0초(기존 제목·시계)·2.6초(`사진 읽고 약 찾는 중 · 2초`, 도는 아이콘)·22초(노랑 안내와 1분 문장), 답변 0.8초(기존 `답변을 만드는 중…`)·2.6초(`답변 만드는 중 · 2초`)·16초(노랑 안내)를 확인함. 검색·사진은 360 폭, 사진·답변은 1280·1024 폭에서 봄. 초 숫자 칸이 `role="timer"`·`aria-live="off"`이고 둘레가 `role="status"`임을 확인함. `npm run lint`·`npm run build` 통과.
- 리뷰 반영(답변 노랑 안내가 화면 밖에 붙는 문제): 대화가 화면을 넘는 대화방(1280 폭)에서 맨 아래를 보는 채 질문을 보내면 16초에 노랑 안내까지 보이게 맨 아래로 따라 내려감(남은 거리 1px 이하), 위로 올려 읽는 중이면 그대로 둠을 확인함. 미리보기 창이 가려진 상태라 스크롤은 동작 줄이기(바로 이동)로 바꿔 쟀음.
