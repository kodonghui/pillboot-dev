# v3 2차 · 대화로 일정 바꾸기 카드(TASK-030)

- 범위: CHT-02 상담 화면. 일정 요청으로 갈린 질문의 답변 말풍선 안 일정 확인 카드(`proposal.kind: SCHEDULE`). 카드 없는 안내(어느 약인지 묻기·일정을 읽지 못함·지금과 같음·규칙 밖 값·장애)는 서버 고정 안내라 지금 답변 모양 그대로임.

- 목업: `design/mockups/v3-2/chat-schedule/`(`pending-a`·`pending-b` 일정 있는 약 "가상정 아침 8시 한 알로 바꿔 줘", `new-a`·`new-b` 일정 없는 약 "예시캡슐 오늘부터 2주 동안 먹을래", `changed-a`·`changed-b` 확정했는데 그사이 일정이 바뀜(409 `SCHEDULE_CHANGED`), `done` 확정한 카드, `closed` 취소한 카드·시간이 지난 카드·약을 지운 카드).

## 표시와 전환

| 상태·응답 | 표시 |
| --- | --- |
| 대기(만료 전) | 확인 카드 |
| 마감 시각이 지남(화면을 열어 둔 채) | `expiresAt`에 맞춰 화면에서 바로 시간이 지난 카드로 바꿈(서버를 다시 부르지 않음) |
| 대기인데 `schedule.myDrugId`가 null | 약을 지운 카드(서버를 부르지 않음, 버튼 없음): 휴지통 아이콘 + `약목록에서 지운 약이에요`, `카드를 만든 뒤 이 약을 약목록에서 지워서 일정을 바꿀 수 없어요. 아무것도 바꾸지 않았어요.` |
| `이 일정으로 바꾸기`를 누름 | 버튼 `바꾸는 중…`, 카드 전체 비활성 |

| 409 `SCHEDULE_CHANGED`(돌려받은 카드의 `myDrugId`가 null) | 약을 지운 카드 |
| 409 `PROPOSAL_ALREADY_CONFIRMED` | 돌려받은 카드를 확정 카드로 보이고 위에 `다른 화면에서 이미 바꾼 카드예요. 더 바꾸지 않았어요.` |

| 409 `PROPOSAL_EXPIRED` | 시간이 지난 카드 |
| 400 | 화면이 `itemNos`를 보내지 않으므로 오지 않아야 함. 오면 버튼 위 빨간 안내로 서버 문구를 보임 |
| 404 | 버튼 위 빨간 안내 `이 카드를 찾을 수 없어요. 대화를 다시 열어 주세요.` |
| 503·연결 끊김 | 버튼 위 빨간 안내 `지금은 일정을 바꾸지 못했어요. 잠시 뒤 다시 눌러 주세요.` 서버가 저장했는지 모르므로 5xx·응답 없음이면 `GET /api/chat-proposals/{id}`로 다시 읽어 그 상태를 보임(개발 프록시·앞단은 끊김을 502·504로 바꿔 줌) |
| 401 | 기존 로그인 만료 처리 |
| `취소` → 200 | 취소한 카드: 금지 아이콘 + `취소했어요`, `14:03에 취소해서 일정을 바꾸지 않았어요.`, `바꾸려던 일정: 가상정 08:00 · 1개`(약 이름 + 바뀐 뒤 복용 시간 · 1회 개수). 확인 창은 두지 않음 |
| `취소` → 409 `PROPOSAL_ALREADY_CONFIRMED` | 확정 카드 + `다른 화면에서 이미 바꾼 카드라 취소하지 않았어요.` |
| `취소` → 409 `PROPOSAL_EXPIRED`·404·503·끊김 | 등록 제안 카드와 같음(503·끊김 문구는 `지금은 취소하지 못했어요. 잠시 뒤 다시 눌러 주세요.`) |
| 시간이 지난 카드 | 시계 아이콘 + `확정할 수 있는 시간이 지났어요`, `카드는 30분 동안만 쓸 수 있어 15:40에 끝났어요. 일정은 그대로예요. 바꾸려면 원하는 일정을 다시 말해 주세요.`, 바꾸려던 일정 요약 |

- 상담 기록을 다시 열면 카드는 서버의 지금 상태(대기·확정·취소·만료)로 보임. 확정 카드는 확정한 '바뀐 뒤' 값을 보이고, 그 뒤 달력에서 일정을 또 고쳐도 카드는 바꾸지 않음(그때 확정한 기록임).
- 확정한 뒤 복용 달력·약목록은 다시 열 때 서버 값을 읽음. 상담 화면이 다른 화면 값을 따로 고치지 않음.

## 읽어 주기·접근

- 카드는 제목으로 이름 붙인 구역. A안은 숨긴 제목 `지금 일정과 바뀐 뒤 일정`이 붙은 표(열 머리 `지금`·`바뀐 뒤`, 행 머리 항목 이름). B안은 정의 목록이고 바뀐 값은 `지금 …`·`바뀐 뒤 …`로 읽힘(취소선·화살표는 꾸밈).
- 바뀐 값은 색만으로 나누지 않음: A안은 `바뀜` 글자, B안은 `바뀌는 값` 묶음 제목과 화살표 앞뒤 순서.
- 확정·취소·시간이 지난 카드로 바뀔 때 제목을 `role="status"`로 읽고, 오류 안내는 `role="alert"`.
- 버튼은 44px 이상(등록 제안과 같은 버튼).

## 문구 차이(TASK-031에서 맞춤, CT가 정함)

- 서버 안내 `UNREADABLE`의 '일정을 그만두거나 지우는 일은 캘린더에서 할 수 있어요'는 화면 이름 '복용 달력'과 다름. TASK-031에서 서버 문구를 '복용 달력에서 할 수 있어요'로 바꿈(명세 8.4도 같음).

## 검증 범위

- 목업 캡처: 8장면 × 360·1280 폭 16장(`captures/`). 상담 화면 틀은 v3-2 답변 진행 목업(실제 화면을 가짜 API로 띄워 저장한 것)이고 대화와 카드만 바꿔 넣음. 카드 틀은 구현된 `src/components/ChatProposal.css`를 그대로 쓰고 일정 부분만 `chat-schedule.css`에 둠. 카드가 길어 캡처할 때만 대화 영역을 펼쳐 찍음(실제 화면은 대화 영역 안에서 스크롤함). 360은 마지막 대화 묶음만(`closed`는 대화 영역 전체) 자른 2배 캡처임.
- 확인한 것: 360·1280에서 기간·시각·안내·버튼 줄바꿈. 처음 찍었을 때 A안 360 기간이 `11월 / 1일부터`처럼 네 줄로 끊겨 좁은 폭에서 항목 이름을 위로 올리고, 기간은 `부터` 뒤에서만 줄을 바꾸게 고침.
- 아직 안 한 것(목업 때): 실제 서버 응답으로 본 카드, 화면 읽기 낭독, 실제 기기, 다크 모드. 409·404·503·끊김은 표로만 정했고 목업은 409 `SCHEDULE_CHANGED`만 그림.
