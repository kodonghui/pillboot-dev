# v3 1차 · 관계 '지인·기타'(TASK-020)

- 범위: PRF-02 프로필 추가·PRF-03 프로필 수정의 관계 선택, PRF-01 프로필 목록·머리말 프로필 전환의 관계 이름표. 새 화면은 없음.
- 추적: V3-COMMON-004, V3-REQ-78, DEC-012. 서버 값은 `OTHER`(TASK-019, develop 반영됨), 이름표는 `지인·기타`.
- API: 기존 `POST /api/profiles`·`PUT /api/profiles/{profileId}`의 `relationshipType`에 `OTHER`를 보냄. 새 API 없음.
- 목업: `design/mockups/v3-1/relation-other/`(`prf02-a`·`prf02-b`, 공통 `prf01`, 캡처 `*-focus.png`는 입력 카드만 자른 것).
- 상태: A안으로 정함(DEC-020, 2026-11-02 PM "1A 2A 3A 4A 5A 6A"). 구현은 TASK-020(`ProfileForm` 관계 칩, `relationLabels.OTHER`). B안 목업·캡처는 비교 기록으로 남김.

## 후보

| 안 | 모양 | 장단점 |
| --- | --- | --- |
| A | 관계 칩을 `본인` · `가족` · `지인·기타` 셋으로. `지인·기타`를 고르면 상세 관계 칸이 없음. 칩 아래 `가족이 아닌 사람(친구·이웃·돌봐 드리는 분 등)이면 지인·기타를 골라 주세요.` | 가족이 아닌 사람을 '가족' 아래에 두지 않아 말이 맞음. 칩이 하나 늘어남 |
| B | 지금 구조 그대로, `가족`의 상세 관계 목록 맨 끝에 `지인·기타`를 더함 | 바뀌는 곳이 가장 적음. '가족'을 고른 뒤 '지인'을 고르는 말의 어긋남이 있음 |

## 표시와 전환

| 상태 | 화면 |
| --- | --- |
| PRF-01·머리말 | `relationLabels.OTHER = '지인·기타'`. 지금은 이름표가 없어 `OTHER`가 그대로 보임(목업 `prf01`은 고친 뒤 모습) |
| PRF-02 A | `지인·기타` 칩을 고르면 `relationshipType: 'OTHER'`로 저장. 상세 관계 필수 검사는 `가족`일 때만 |
| PRF-02 B | 상세 관계 `지인·기타`를 고르면 `OTHER`로 저장 |
| PRF-03 | 저장된 `OTHER` 프로필을 열면 A는 `지인·기타` 칩이, B는 `가족` + 상세 `지인·기타`가 골라진 상태 |
| 저장 오류 | 기존 프로필 저장 오류 안내 그대로 |

- 본인 프로필이 이미 있으면 `본인` 칩이 잠기는 기존 규칙은 그대로임.
- 카카오 자동 프로필(V3-KAKAO-002)이 만든 `OTHER` 프로필도 같은 이름표로 보임.

## 검증 범위

- 목업 캡처: 360·1280 폭에서 PRF-02 A·B와 PRF-01 이름표를 찍어 봄.
- 구현(TASK-020, A안): 가짜 API에서 확인함. 1280 폭: PRF-01 목록과 머리말 '관리할 사람' 목록에 `OTHER` 프로필이 `지인·기타`로 보임. PRF-02에서 본인 잠김 상태로 `본인`·`가족`·`지인·기타` 칩과 안내 두 줄이 보이고, `지인·기타`를 고르면 상세 관계 칸이 사라짐. 저장 요청 `relationshipType: "OTHER"`(가짜 API 기록)와 목록 반영을 봄. PRF-03에서 `OTHER` 프로필이 `지인·기타` 칩 골라진 채 열리고, `가족`으로 바꿔 저장하면 상세 관계 오류와 포커스, 다시 `지인·기타`로 바꾸면 오류가 사라지고 `OTHER`로 저장됨. 360 폭: 칩 세 개가 한 줄(높이 48), 문서 폭 360. 안내 줄은 관계 묶음의 `aria-describedby`로 이음. `npm run lint`·`npm run build` 통과.
- 아직 안 한 것: 실제 서버 저장, 카카오 자동 프로필이 만든 `OTHER` 프로필, 화면 읽기 낭독.
