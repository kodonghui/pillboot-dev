# v3 3차 · 카카오톡 약봉이 말풍선(TASK-034~038)

- 범위: 카카오톡 1:1 채팅에서 지인이 보는 약봉이 말풍선과 빠른 답장. 첫 연결, 메시지 묶기·스위치 안내, 사진·글 등록 제안과 확정·취소, 음성, 일정 바꾸기. 운영자 연결 해제·삭제(V3-KAKAO-010)는 관리 명령이라 지인에게 새 말풍선이 없고, 해제 뒤 다시 말을 걸면 첫 연결부터 다시 나옴. 단체방 안내·`더 보기`·`도움말`·`새 대화`·`내 약`은 지금 다리(`카톡 다리`) 그대로임.
- 추적: V3-KAKAO-001~010, V3-REQ-53~65·78·79, V3-FL-24~26, DEC-001(확정 전에는 저장하지 않음), DEC-003·011·012·013·016, DEC-023(이름마다 하나 고르기), DEC-025(바뀌는 값 먼저). 웹 카드의 내용·상태 규칙은 `v3-2-chat-proposal.md`·`v3-2-chat-schedule.md`를 따르고, 카톡에서 달라지는 것만 여기 적음.
- API: `POST /api/profiles`(관계 `OTHER`), `POST /api/chat-sessions/{sessionId}/messages`의 `answer.proposal`, `POST /api/chat-sessions/{sessionId}/photos`, `GET /api/chat-proposals/{proposalId}`, `POST .../confirm`(`itemNos`)·`POST .../cancel`, `POST /api/voice-transcriptions`, `DELETE /api/profiles/{profileId}`. 새 API는 없음.
- 목업: `design/mockups/v3-3/kakao/`(`start-a`·`start-b` 첫 연결, `start-edge` 잘못된 값·30분 지남·서버 오류, `photo-a`·`photo-b` 처방전 사진 제안, `schedule` 일정 바꾸기, `notices` 음성·스위치·글자 수 안내). 캡처는 360 폭만 찍음(카카오톡 휴대폰 화면).
- 상태: 1은 A안(하나씩 묻기), 2는 B안(이름마다 하나 고르기)으로 정함(DEC-027, PM 선택 버튼 "A안 하나씩 묻기 (추천)"·"B안 이름마다 하나 (추천)", 2026-11-03 11:17 KST 이 세션, 선택 페이지). 고르지 않은 안의 목업·캡처는 고른 근거로 남겨 둠. 다리 구현은 `카톡 다리 저장소`의 TASK-034~038 브랜치에서 함.

## 공통 규칙

- 말투는 지금 다리 문구(`yakbong/texts.py`)와 필받음 화면의 해요체를 따름.
- 한 답은 말풍선 3개까지(카카오 `simpleText`). 넘으면 지금처럼 `더 보기`로 나눔.
- 빠른 답장은 마지막 답에만 보이고, 누르면 그 글자가 지인 메시지로 감. 글자는 14자 이하, 10개 이하(카카오 제한). 같은 글자를 직접 쳐도 같은 뜻으로 받음.
- 빠른 답장 글자는 다리가 그 지인의 지금 상태(묻는 중인 값, 대기 중인 제안)에 맞춰 읽음. 상태가 없을 때 같은 글자가 오면 보통 질문으로 넘김.
- 카톡 화면은 줄을 앱이 바꾸므로 목록은 줄마다 `·`나 번호로 시작하게 씀.
- 빠른 답장이 카톡에 보이지 않을 수 있어, 꼭 골라야 답이 이어지는 말풍선은 보낼 글자를 글로도 적음(아래 '버튼이 보이지 않을 때').

## 버튼이 보이지 않을 때(2026-11-04)

- 왜: PM 카톡에서 첫 연결 성별 단계의 빠른 답장이 보이지 않았음. PM 말 "카톡에서 뭐 버튼 안나오는데? 이거 설정 어케해?"(2026-11-04 Claude Code 대화). 다리 로그에는 그 턴들의 콜백이 모두 성공(`sent:true`, 2026-11-03 22:59Z)으로 남아 카카오는 답을 받았음. 카카오톡 봇 API 문서는 카카오디벨로퍼스에 로그인해야 열려 빠른 답장 지원 여부와 설정은 확인하지 못함.
- 꼭 골라야 답이 이어지는 말풍선(성별, 임신 여부, 등록 제안의 이름 묻기·요약, 일정 바꾸기)은 끝 줄에 보낼 글자를 적음. 예: `‘남성’·‘여성’·‘모름’ 가운데 하나를 보내 주세요.` 빠른 답장은 그대로 같이 보냄(보이는 기기에서는 눌러도 됨).
- 고를 수 없는 글이 오면 `아래 버튼에서 골라 주세요.` 대신 그 질문의 글자를 적은 줄을 보냄. 예: `‘예’·‘아니오’ 가운데 하나를 보내 주세요.`
- 성별은 `남`·`남자`, `여`·`여자`, `몰라`·`모르겠어`도 받음. 임신 여부는 `네`·`응`·`임신 중`, `아니요`·`아뇨`·`아니`·`아님`·`임신 아님`도 받음. 끝에 `요`·`예요`·`이에요`·`에요`·`입니다`가 붙어도 받음(`남자예요`, `몰라요`). 뜻이 하나로 정해지는 낱말만 받고, 그 밖의 글은 다시 물음(다리가 값을 추측하지 않음, A안 그대로).
- 버튼 글자와 띄어쓰기·문장부호만 다른 글은 같은 글자로 받음: `모두등록`, `넣지않음`, `일정바꾸기`, `1 번`, `더보기`, `내약`, `새대화`.
- 다른 버튼 안내도 글자를 적음: `더 보기` 안내는 `(답이 더 있어요. ‘더 보기’를 보내면 이어서 보여 드려요.)`, 503·응답 없음 안내의 `잠시 뒤 다시 눌러 주세요.`는 `잠시 뒤 ‘모두 등록’을 다시 보내 주세요.`(등록), `잠시 뒤 ‘일정 바꾸기’를 다시 보내 주세요.`(일정), `잠시 뒤 ‘취소’를 다시 보내 주세요.`(취소)로 씀.
- 연결됨·`도움말`의 빠른 답장(`내 약`·`새 대화`·`도움말`)은 고르지 않아도 대화가 이어지고 `도움말` 글에 쓰는 말이 적혀 있어 그대로 둠.

## 고를 것 1 · 첫 연결에서 묻는 방식(V3-KAKAO-001·002)

| 안 | 모양 | 장단점 |
| --- | --- | --- |
| A | 하나씩 묻기: 안내 뒤 `어떻게 불러 드릴까요?` → `태어난 해` → 성별 빠른 답장(`남성`·`여성`·`모름`) → (여성·모름이면) 임신 여부(`예`·`아니오`) → 연결 | 질문 하나에 답 하나라 나이 드신 지인도 헷갈리지 않고, 값마다 따로 확인해 다시 물을 값이 분명함. 주고받기가 4~5번이고, 명세 V3-KAKAO-001 수용 기준 '첫 답에 성별 빠른 답장'을 '세 번째 질문에 성별 빠른 답장'으로 고쳐야 함 |
| B | 한 번에 묻기: 안내 뒤 `호칭·태어난 해·성별을 한 번에 보내 주세요. 예: 엄마친구 1965 여성`과 성별 빠른 답장 → 빠진 값만 다시 묻기 → (여성·모름이면) 임신 여부 → 연결 | 다 맞게 보내면 2~3번에 끝나고 명세 수용 기준 그대로임. 띄어쓴 호칭(`엄마 친구`)·`65년생`·순서가 섞인 글을 나눠 읽어야 해서 잘못 읽을 수 있고, 성별 버튼만 먼저 누르면 나머지를 또 쳐야 함 |

- CT 추천: A안. 약봉이를 쓸 지인은 부모님 또래가 많고, 이 단계에서 잘못 읽은 출생연도·성별은 DUR 연령·임부 판단에 그대로 쓰임. 한 번에 하나만 받으면 다리가 값을 추측하지 않음. 반론: 주고받기가 두 배쯤이고, 이미 한 줄로 다 보낸 지인에게도 하나씩 다시 물음(A안도 첫 답에 세 값이 다 맞게 오면 한 번에 받도록 만들 수 있으나, 그만큼 B안의 읽기 문제를 함께 가짐).

| 음성 스위치가 꺼졌는데 음성이 옴 | `지금은 음성을 받지 않아요. 궁금한 점을 글로 보내 주세요.` |
| 이모티콘·그 밖의 형식만 옴 | `이모티콘은 읽지 못해요. 글이나 사진으로 보내 주세요.`(켜진 스위치에 맞춰 `글`·`사진`·`음성`을 고름) |

- 꺼진 형식과 글이 한 묶음이면 글에 답하고 안내를 첫 말풍선에 둠. 꺼진 형식만 왔으면 서버를 부르지 않음.
- 묶기를 꺼도 말풍선은 같고 메시지마다 답함.
- 구현에서 정한 것(TASK-035, CT, DEC-019): 안내는 답을 쪽으로 나누기 전에 맨 앞 문단으로 넣음. 첫 말풍선에 자리가 없어 안내가 따로 말풍선이 되어도 금기 안내·근거는 첫 쪽에 남음. 앞 답을 기다리는 메시지는 받은 뒤 마감까지 30초가 남지 않으면 앞 답을 기다리지 않고 그 메시지에 바로 `질문이 한꺼번에 많이 와서 이 질문에는 답하지 못했어요. 한 번에 하나씩 다시 보내 주세요.`를 보냄. 앞 답을 기다리는 사이 쌓인 메시지도 받은 때 사이가 조용한 틈보다 길면 따로 묻고 따로 답함.

## 고를 것 2 · 등록 제안에서 고르는 방식(V3-KAKAO-004·005)

글로 한 등록 요청과 처방전 사진이 같은 모양임. 서버 답변 글의 '카드에서 … 확정해 주세요' 문장은 카드가 없는 카톡에 맞지 않아 다리가 아래 말풍선으로 바꾸고, `찾지 못한 이름: …` 줄만 그대로 붙임. 카드 없는 안내(이름 없음·못 찾음·다시 찍기·장애)는 서버 글 그대로임.

| 안 | 모양 | 장단점 |
| --- | --- | --- |
| A | 번호 목록 한 번에: 후보 전체를 이름 묶음별 번호 목록으로 보이고 `모두 등록`(미리 고른 약만)·`1번`·`2번`…·`취소`. 여러 개는 `1 3`처럼 번호를 띄어 보냄. 누르면 바로 확정 | 한 번 눌러 끝나고 말풍선이 하나임. `모두 등록`이 무엇을 넣는지 목록의 ✓를 보고 알아야 하고, 같은 약의 다른 함량을 둘 다 넣을 수 있음(웹 A안과 같은 약점) |
| B | 이름마다 하나 고르기: 미리 고를 수 없는 이름(후보가 둘 이상이거나 함량이 다름)만 하나씩 `1번`·`2번`·`넣지 않음`으로 묻고, 마지막에 넣을 약 요약과 `모두 등록`·`취소` | 웹 카드 B안(DEC-023)과 고르는 법이 같고 한 이름에 한 품목만 들어감. 넣기 전에 요약을 한 번 봄. 헷갈리는 이름이 많으면 그만큼 주고받기가 늘어남 |

- CT 추천: B안. 웹에서 고른 규칙(이름마다 하나, 함량 다른 약을 겹쳐 넣지 않음)을 카톡에도 그대로 두는 편이 안전하고, 보통은 이름마다 함량이 맞는 후보가 하나라 곧바로 요약과 `모두 등록` 한 번으로 끝남. 반론: 함량이 다른 후보만 있는 이름이 여럿이면 질문이 이름 수만큼 늘고, 그사이 30분이 지나면 처음부터 다시 해야 함.

### 두 안 공통

- 미리 고름은 웹과 같음: 이름마다 '함량 일치'이면서 고를 수 있는 후보가 하나뿐이면 그 약.
- 이미 약목록에 있는 후보는 번호 없이 `· 예시서방캡슐 10밀리그램 — 이미 약목록에 있어요`로 보임.
- 약 이름은 기본 이름에 함량을 붙여 씀(`가상정 500밀리그램`, 기본 이름이 없으면 품목명). 함량 배지 대신 `함량 같음`·`함량 다름`·`함량 확인 못 함`을 글로 붙임.
- 마감은 첫 말풍선 첫 줄에 `16:15까지 고를 수 있어요`.
- 다른 지인의 제안은 처리하지 않음: 빠른 답장 글자는 그 지인의 마지막 대기 제안에만 씀.

| 결과 | 말풍선 |
| --- | --- |
| 확정 200 | `약목록에 2개를 넣었어요.`<br>`· 가상정 500밀리그램`<br>`· 예시캡슐 10밀리그램`<br>`복용 시각은 '가상정 아침 8시에 먹어'처럼 말해 주시면 일정으로 바꿔 드려요.` |
| 다시 눌렀는데 이미 확정(409 `PROPOSAL_ALREADY_CONFIRMED`) | `이미 넣은 약이에요. 더 넣지 않았어요.` + 처음 넣은 약 목록 |
| 취소 200 | `취소했어요. 약목록에 아무것도 넣지 않았어요.` |

| 시간 지남(409 `PROPOSAL_EXPIRED`) | `고를 수 있는 시간(30분)이 지났어요. 약목록에 아무것도 넣지 않았어요. 넣으려면 약 이름이나 사진을 다시 보내 주세요.` |
| 그사이 약목록에 들어감(409 `CONFLICT`) | `고른 약 중 ‘가상정 500밀리그램’이 그사이 약목록에 들어가 있어서 아무것도 넣지 않았어요.` + 남은 후보로 다시 고르기(A안 목록·B안 요약) |
| 404 | `이 제안을 찾을 수 없어요. 약 이름이나 사진을 다시 보내 주세요.` |
| 503·응답 없음 | 제안을 다시 읽어 확정됐으면 확정 200과 같게, 아니면 `지금은 약목록에 넣지 못했어요. 잠시 뒤 ‘모두 등록’을 다시 보내 주세요.` |
| 대기 제안이 없는데 `모두 등록`·`취소`·`1번` | 보통 질문으로 넘김 |

### A안

| 말풍선 | 빠른 답장 |
| --- | --- |
| `16:15까지 고를 수 있어요`<br>`‘가상정 500’에서 찾은 약`<br>`1. ✓ 가상정 500밀리그램 · 함량 같음`<br>`2. 가상정 250밀리그램 · 함량 다름`<br>`‘예시캡슐’에서 찾은 약`<br>`3. 예시캡슐 10밀리그램 · 함량 확인 못 함`<br>`· 예시서방캡슐 10밀리그램 — 이미 약목록에 있어요` | — |
| `‘모두 등록’은 ✓ 표시한 약만 넣어요. 다른 약은 번호를 눌러 하나만 넣거나, 여러 개면 번호를 띄어 보내 주세요. 예: 1 3` | `모두 등록` `1번` `2번` `3번` `취소` |

- 미리 고른 약이 없으면 `모두 등록`을 빼고 둘째 말풍선을 `넣을 약의 번호를 눌러 주세요. 여러 개면 번호를 띄어 보내 주세요. 예: 1 3`으로 씀.
- 번호 빠른 답장은 8개까지. 그 뒤 번호는 글로 보냄. 대기 제안이 있을 때 숫자와 띄어쓰기·쉼표만으로 된 글은 번호 고르기로 받음(V3-KAKAO-005의 '글 → 새 턴'에서 이 경우만 뺌).

### B안

| 순서 | 말풍선 | 빠른 답장 |
| --- | --- | --- |
| 고를 이름(미리 고를 수 없는 이름마다) | `16:15까지 고를 수 있어요`<br>`‘예시캡슐’에서 찾은 약이에요. 어느 약인가요?`<br>`1. 예시캡슐 10밀리그램 · 함량 확인 못 함`<br>`2. 예시캡슐 20밀리그램 · 함량 확인 못 함`<br>`‘1번’·‘2번’·‘넣지 않음’ 가운데 하나를 보내 주세요.` | `1번` `2번` `넣지 않음` |
| 요약 | `이 약을 약목록에 넣을까요?`<br>`· 가상정 500밀리그램(사진에서 읽은 함량과 맞아 미리 골랐어요)`<br>`· 예시캡슐 10밀리그램`<br>`‘모두 등록’·‘취소’ 가운데 하나를 보내 주세요.` | `모두 등록` `취소` |

- 미리 고를 수 있는 이름만 있으면 곧바로 요약이 나옴.
- `넣지 않음`으로 고른 이름이 있으면 요약 끝에 `넣지 않는 이름: 예시캡슐`을 붙임.
- 모든 이름을 `넣지 않음`으로 고르면 요약 대신 제안을 취소하고 `넣을 약을 고르지 않아 아무것도 넣지 않았어요.`
- 고르는 중에 다른 글이 오면 고르기를 멈추고 그 글을 새 질문으로 받음. 제안은 서버에서 대기로 남아 30분 뒤 끝남.

### 구현에서 정한 것(TASK-036, CT, DEC-019)

- 사진 스위치는 기본 켜짐임. 사진은 카카오 CDN 주소(https, `kakaocdn.net`)에서만 넘겨주기 없이 10MB까지 받고, 파일 머리로 알아낸 형식(JPG·PNG·WEBP)의 확장자·Content-Type으로 서버에 보냄(서버가 셋이 맞는지 봄). 주소는 로그·기록에 남기지 않음.

| 경우 | 말풍선 |
| --- | --- |
| 한 묶음에 사진이 둘 이상 | `사진은 한 번에 한 장만 읽어요. 처방전·약봉투 사진을 한 장씩 보내 주세요.` 서버를 부르지 않음. 글도 같이 왔으면 그 위에 아래 줄의 '같이 보낸 글' 안내 |
| 사진과 글이 한 묶음 | 사진으로 제안을 만들고 글은 묻지 않음. 첫 말풍선 위에 `사진과 같이 보낸 글에는 이번에 답하지 않았어요. 궁금한 점은 다시 보내 주세요.` |
| 사진 받기 실패·주소 만료 | `사진을 받지 못했어요. 다시 보내 주세요.` |
| 사진이 10MB를 넘음 | `사진은 10MB 이하만 읽을 수 있어요. 더 작게 다시 보내 주세요.` |
| JPG·PNG·WEBP가 아님 | `JPG·PNG·WEBP 사진만 읽을 수 있어요. 다시 찍어 보내 주세요.` |
| 이름을 묻는 중에 범위 밖 번호·`모두 등록`, 요약 뒤에 번호·`넣지 않음` | 이름을 묻는 중이면 그 질문 다시(끝 줄에 보낼 글자가 있음), 요약 뒤면 `‘모두 등록’·‘취소’ 가운데 하나를 보내 주세요.` |
| 확정한 제안을 취소(409 `PROPOSAL_ALREADY_CONFIRMED`) | `이미 약목록에 넣은 제안이라 취소하지 않았어요.` + 넣은 약 목록 |
| 취소가 503·응답 없음 | `지금은 취소하지 못했어요. 잠시 뒤 ‘취소’를 다시 보내 주세요.` |
| 넣을 수 있는 약이 하나도 없음(찾은 약이 모두 이미 약목록에 있음) | 제안을 취소하고 `찾은 약이 모두 이미 약목록에 있어요. 더 넣지 않았어요.` |

- `1번` 대신 `1`도 받음. 이름을 묻는 중에도 `취소`를 치면 제안을 취소함.
- 후보가 모두 이미 약목록에 있는 이름은 묻지 않고 요약 끝에 `이미 약목록에 있는 약: …`을 붙임. 읽은 이름이 없는 후보 묶음은 `찾은 약이에요. 어느 약인가요?`로 물음.
- 미리 고른 약 뒤 괄호: 사진은 `(사진에서 읽은 함량과 맞아 미리 골랐어요)`, 글은 `(말씀하신 함량과 맞아 미리 골랐어요)`.
- 그사이 약목록에 들어감(409 `CONFLICT`): 그 이름에 고를 수 있는 후보가 남았으면 그 이름을 다시 묻고, 없으면 요약에서 뺌. 넣을 약이 남지 않으면 제안을 취소함.
- 확정 200 말풍선의 예시 문장(`'가상정 아침 8시에 먹어'`)은 넣은 첫 약의 기본 이름으로 씀.
- 고르는 상태는 다리 메모리에만 둠. 확정·취소한 뒤에도 같은 제안을 기억해 `모두 등록`·`취소`를 다시 누르면 서버 답(이미 넣음·취소됨·시간 지남)을 옮기고, 다른 글이 오면 잊음. 다리를 다시 켜면 잊고, 그 뒤 버튼 글자는 보통 질문이 됨. 마감이 지난 뒤 번호를 누르면 서버를 부르지 않고 시간 지남 말풍선을 보냄.
- 고르는 상태는 제안을 받은 프로필에 묶음. 운영자가 `admin link`로 다른 프로필에 이었거나 연결을 끊어 지인이 첫 연결로 들어오면 버리고, 그 뒤 버튼 글자는 보통 질문이 됨(프로필이 모두 다리의 한 계정에 있어 앞 프로필의 제안을 다른 사람 약목록에 넣지 않게 함).
- 알약 사진(V3-KAKAO-011)은 PM 결정 대기이며 `v3-chat-pill-photo.md`에 있음(2026-11-04). 정하기 전에는 위 규칙 그대로임(사진은 처방전·약봉투로 읽고, 한 묶음에 두 장이면 한 장씩 보내 달라고 함).

## 음성(V3-KAKAO-006)

| 경우 | 말풍선 |
| --- | --- |
| 받아씀 | 답의 첫 말풍선 첫 줄에 `🎤 “타이레놀 등록해 줘”로 들었어요.` 그다음은 글로 보낸 것과 같은 답 |

| 형식 미지원·받아쓰기 실패·빈 결과·음성 받기 실패 | `음성을 받아쓰지 못했어요. 글로 보내 주세요.` |

- 받아쓴 글을 한 줄 보여 주는 것은 CT가 정함(DEC-019): 잘못 들은 말로 제안이 나와도 지인이 알아챌 수 있게 함. 저장은 어차피 확정 뒤에만 됨.
- 구현에서 정한 것(TASK-037, CT, DEC-019)
  - 음성 스위치(`voice`)는 기본 꺼짐임. 실제 카톡 음성 메시지 형식(H-01)을 확인한 뒤 켬. 꺼져 있으면 `지금은 음성을 받지 않아요. 궁금한 점을 글로 보내 주세요.`
  - 음성은 카카오 CDN 주소(https, `kakaocdn.net`)에서만 넘겨주기 없이 5MB까지 받고, 파일 머리로 알아낸 형식(m4a·WAV)으로 서버에 보냄. 주소와 받아쓴 글은 로그·기록에 남기지 않음.
  - 한 묶음에 음성이 여럿이면 받은 순서대로 받아쓰고, 같이 온 글과 받은 순서대로 합쳐 한 번 물음. 들은 글 줄은 음성마다 한 줄씩 첫 문단에 둠. 제안 말풍선에서는 마감 줄보다 위에 둠.
  - 하나라도 받아쓰지 못하면 그 묶음은 묻지 않음(같이 온 글도). 일부만 물으면 음성 내용이 빠진 답이 되기 때문임. 같은 묶음의 꺼진 형식 안내는 받아쓰기 실패 안내 위에 둠.
  - 음성과 사진이 한 묶음이면 글과 사진이 같이 온 것과 같게 사진만 읽고 `사진과 같이 보낸 글에는 이번에 답하지 않았어요. …` 안내를 붙임.

## 일정 바꾸기(V3-KAKAO-007)

DEC-025(바뀌는 값 먼저)를 말풍선으로 옮김. 서버 답변 글의 '카드에서 … 확정해 주세요' 문장은 다리가 이 말풍선으로 바꿈.

| 경우 | 말풍선 | 빠른 답장 |
| --- | --- | --- |
| 일정 있는 약 | `16:15까지 확정할 수 있어요`<br>`가상정 복용 일정을 바꿀까요?`<br>`바뀌는 값`<br>`· 복용 시간: 07:00 · 12:00 · 18:00 → 08:00`<br>`· 1회 개수: 2개 → 1개`<br>`그대로 두는 값`<br>`· 기간: 11월 1일부터 11월 30일까지`<br>`· 복용 때: 식후`<br>`확정하기 전에는 지금 일정이 그대로예요.`<br>`‘일정 바꾸기’·‘취소’ 가운데 하나를 보내 주세요.` | `일정 바꾸기` `취소` |
| 일정 없는 약 | `예시캡슐에는 지금 일정이 없어요. 이 일정을 새로 넣을까요?` + 네 값 + `말씀하지 않은 값은 기본 일정(오늘 하루, 07:00 · 11:00 · 17:00)으로 채웠어요.` + `‘일정 바꾸기’·‘취소’ 가운데 하나를 보내 주세요.` | `일정 바꾸기` `취소` |
| 확정 200 | `가상정 일정을 바꿨어요.`<br>`· 복용 시간 08:00 · 1회 1개`<br>`· 11월 1일부터 11월 30일까지` | — |
| 409 `SCHEDULE_CHANGED`(약 있음) | `제안을 만든 뒤 가상정 일정이 바뀌어서 바꾸지 않았어요. 원하는 일정을 다시 말해 주세요.` | — |
| 409 `SCHEDULE_CHANGED`(약 지움)·대기 제안의 약이 지워짐 | `약목록에서 지운 약이라 일정을 바꾸지 않았어요.` | — |
| 취소 200 | `취소했어요. 일정은 그대로예요.` | — |
| 409 `PROPOSAL_EXPIRED`·`PROPOSAL_ALREADY_CONFIRMED`·`PROPOSAL_CANCELLED`·404·503 | 등록 제안과 같은 문장에서 `약목록에 넣지`를 `일정을 바꾸지`로 바꿔 씀 | — |

- 지금 1회 개수가 확인되지 않은 약은 웹과 같이 `-`로 보임.
- 서버 안내 `UNREADABLE`의 '일정을 그만두거나 지우는 일은 복용 달력에서 할 수 있어요.'는 웹에 들어오지 않는 지인에게 맞지 않아, 다리가 이 문장만 빼고 옮김(CT가 정함, DEC-019).

### 구현에서 정한 것(TASK-037, CT, DEC-019)

등록 제안 문장을 일정에 맞게 바꾼 문장은 아래와 같음. '다시 보내 주세요'는 일정에 맞게 '원하는 일정을 다시 말해 주세요'로 씀.

| 경우 | 말풍선 | 빠른 답장 |
| --- | --- | --- |
| 취소한 제안을 확정 | `취소한 제안이에요. 바꾸려면 원하는 일정을 다시 말해 주세요.` | — |
| 마감 지남(409 `PROPOSAL_EXPIRED`) | `확정할 수 있는 시간(30분)이 지났어요. 일정을 바꾸지 않았어요. 바꾸려면 원하는 일정을 다시 말해 주세요.` | — |
| 제안 없음(404) | `이 제안을 찾을 수 없어요. 원하는 일정을 다시 말해 주세요.` | — |
| 이미 확정한 제안을 확정 | `이미 바꾼 일정이에요. 더 바꾸지 않았어요.` + 바뀐 일정 두 줄 | — |
| 이미 확정한 제안을 취소 | `이미 바꾼 일정이라 취소하지 않았어요.` + 바뀐 일정 두 줄 | — |
| 확정이 503·응답 없음이고 다시 읽어도 확정 전 | `지금은 일정을 바꾸지 못했어요. 잠시 뒤 ‘일정 바꾸기’를 다시 보내 주세요.` | `일정 바꾸기` `취소` |
| 취소가 503·응답 없음 | `지금은 취소하지 못했어요. 잠시 뒤 ‘취소’를 다시 보내 주세요.` | `일정 바꾸기` `취소` |

- 확정이 503·응답 없음이면 제안을 다시 읽어 확정됐으면 `… 일정을 바꿨어요.` 말풍선을 보냄(등록 제안과 같음).
- 일정이 없던 약의 말풍선에도 맨 위에 `HH:MM까지 확정할 수 있어요` 줄을 둠. 1회 개수뿐 아니라 어느 값이든 없으면 `-`로 보임.
- 확정은 본문 없이 보냄(일정 제안은 `itemNos`가 없음).
- 다른 글이 오면 제안을 두고 그 글에 보통 답을 함. 제안은 서버에서 30분 뒤 끝나고, 그 뒤 `일정 바꾸기`·`취소` 글자는 보통 질문이 됨.
- 일정 제안 상태도 등록 제안과 같이 제안을 받은 프로필에 묶음. 연결이 다른 프로필로 바뀌면 버림.
- 기간이 두 해에 걸치면 날짜에 연도를 붙임: 제안의 `current`·`proposed` 시작일·종료일 가운데 연도가 둘 이상이면 대기·확정·이미 확정 말풍선의 날짜를 모두 `2027년 11월 1일부터 2027년 11월 30일까지`처럼 보임. 확정 말풍선도 바뀐 뒤 기간만이 아니라 대기 말풍선과 같은 `current`·`proposed`로 정해, 1년 미룬 제안이 확정 뒤에 연도 없이 보이지 않게 함. 일정이 없던 약은 `current` 날짜가 없어 바뀐 뒤 기간만으로 정함. 웹 카드(`v3-2-chat-schedule.md`, PR #23)와 같은 규칙임(카톡 다리 PR #4·#8).

## 연결 해제와 삭제(V3-KAKAO-010)

- 지인에게 보내는 새 말풍선은 없음. 운영자가 `admin unlink`(해제만)·`admin delete`(해제와 기록 삭제)를 실행함. 해제 뒤 그 지인이 말을 걸면 시작 안내부터 다시 나오고 새 프로필로 연결됨.
- 운영자 명령의 출력은 지금처럼 `#짧은키`와 프로필 번호만 보이고 호칭·카카오 키 원문은 보이지 않음.
- 구현에서 정한 것(TASK-038, CT, DEC-019)
  - `admin delete <#키> [옛 프로필 번호]`: 연결이 있으면 끊고 해제 기록의 옛 프로필을 지움. 번호를 주면 해제 기록의 그 프로필만 지우고 지금 연결은 그대로 둠(해제 뒤 다시 말을 걸어 새 프로필로 이어진 지인). `admin unlinks`로 아직 지우지 않은 옛 프로필을 봄.
  - 다리의 다른 연결이 지금 쓰는 프로필은 지우지 않음. 운영자가 한 프로필에 여러 사람을 이었을 수 있어서, 한 사람의 삭제 요청으로 다른 사람의 약목록이 지워지지 않게 함. 해제 기록은 남아 그 연결을 끊은 뒤 다시 실행할 수 있음.
  - 지우지 못하면(오류·마지막 프로필 409) 명령이 실패로 끝나고 해제 기록이 남음.
  - 다리의 `people` 행(카카오 키·처음·마지막으로 본 때)과 해제 기록 행은 남김. 그 지인이 다시 말을 걸 수 있고, 해제 기록은 무엇을 언제 지웠는지 보이는 근거임. 대화 내용은 원래 다리에 없음.

## 검증 범위

- 목업 캡처: 7장면 × 360 폭(2배). 카카오톡 채팅방을 흉내 낸 정적 HTML이고, 실제 카카오톡의 글꼴·줄바꿈·빠른 답장 가로 스크롤과 다를 수 있음. 빠른 답장은 캡처에서 모두 보이게 줄을 바꿔 그림(실제 앱은 한 줄로 옆으로 밀어 봄).
- 확인한 것: 360 폭에서 말풍선 줄바꿈과 빠른 답장 글자 수(14자 이하).
- 아직 안 한 것: 실제 카카오톡 화면(봇 연결은 운영 서버 다리, 3차 배포 승인 뒤), 화면 읽기, 다크 모드, PC 카카오톡.
- 2026-11-04 실제 카카오톡(PM 휴대폰)에서 첫 연결 성별 단계의 빠른 답장이 보이지 않았음. 그래서 보낼 글자를 글로 적고 같은 뜻의 낱말을 받게 바꿈(위 '버튼이 보이지 않을 때'). 빠른 답장이 왜 안 보이는지(카카오톡 봇 API 지원 여부·설정)는 확인 전임.
