# 실행 2026-11-04 약봉이 카톡 사용 편의 QA(1·2차)

- 왜: PM 운영 카톡에서 요약 단계에 `ㅇㅇ 그리고 오늘부터 5일간 점심에 먹을거니까 그거도 등록해줘`를 보내자 `카드에서 선택하고 확정해 주세요`·`앱에서 등록해 주세요`가 나오고, 사과가 되풀이되고, 답마다 긴 `[근거]`가 붙음. 지인 의견도 같은 쪽이었음(처음 쓰는 사람은 도움말을 누르지 않으면 쓰는 법을 모름). PM 요청 "시나리오를 정해 QA를 충분히 돌리고 사용자 편의 문제를 고쳐 달라"(2026-11-04, Claude Code 대화)에 따름.
- 화면정의서: [v3-3-kakao.md](../../../react-client/design/v3-3-kakao.md) '첫 연결'·'고르는 중의 말'·'줄여 말한 내 약'·'[근거]와 금기 안내 줄', [v3-kakao-web-link.md](../../../react-client/design/v3-kakao-web-link.md) '프로필 고르기·바꾸기'·'묻는 말에 바로 답하기'.
- 환경: 운영 서버 안의 임시 QA 서버. 필받음 API는 127.0.0.1:18190, 약봉이 다리 시험 하네스는 127.0.0.1:18191(터널 없음)임. 서버 jar와 다리는 이 작업의 고친 코드(팀 저장소 `fix/kakao-ask-in-moment`, 카톡 다리 `fix/ask-in-moment`)이고, OpenAI·공공데이터는 운영과 같은 설정을 씀. DB는 버리는 MySQL. 카카오 채널은 부르지 않고 하네스가 카카오 메시지 모양으로 다리를 부름.
- 운영에 닿지 않게 한 것: 운영 DB와 운영 서비스는 읽지도 고치지도 않음. 키는 서버 밖으로 나오지 않음.
- 방법: 페르소나마다 하위 에이전트 하나가 `say <사용자ID> "<글>"`(사진 `--photo`, 묶음 `--batch`, 웹 회원 `webuser`)만 써서 실제 사람처럼 말함. 문제를 찾으면 비슷한 말 2~3개로 다시 보내 재현을 봄. 사진은 합성 처방전(`2026-11-04-stage-api/rx-qa.jpg`)임.
- 페르소나(1·2차 같음): A 67세 어머니(처음 씀), B 급한 직장인(등록·일정), C 웹 회원 보호자(프로필 엄마·아빠), D 깐깐한 테스터(번호·명령·긴 글), E 50대 남성(여러 약, 이름 줄임).
- 대화 원문은 저장소에 넣지 않음(QA 사용자는 합성이지만 길고, 다시 만들 수 있음).

## 안 됨·남은 것

- 점심 기본 시각이 11:00이라 이르다는 인상(B·E). 아침·점심·저녁 07:00·11:00·17:00은 웹 화면과 같은 제품 기본값이라 이번에는 바꾸지 않고 카톡 일정 제안에 그 시각과 바꾸는 말을 한 줄로 알림. 바꿀지는 팀이 정함.
- 내 약이 없는 사람의 일반 질문(`약 빼먹으면 어떡해`)과 불만(`왤캐 대답이 유연하지가 못해`)은 서버 고정 안내(`아직 등록한 약이 없어…`)로 답함. 공식 근거 없이 모델이 답하지 않는다는 서버 원칙(V3-REQ-62)대로라 바꾸지 않음.
- 공식 자료를 확인하지 못했다고 말한 답에도 `[근거]`가 붙는 경우(D). 서버가 그 약의 자료를 받았다고(ok) 표시한 경우라 다리가 가를 수 없음.
- `ㅋ`는 주제 밖 고정 안내, `.`는 짧은 도움말로 기준이 다름(하).
