# 실행 2026-11-05 카톡 복약 알림 운영 시험(DEC-033)

- 왜: DEC-033을 운영에 켜기 전에 실제 알림이 오고, 같은 알림이 두 번 오지 않으며, 웹 푸시가 그대로 오는지 확인함.
- 근거: PM "1·2·3 모두 승인"(2026-11-04 밤, 프로젝트 대화). PM 카톡에만 먼저 켜고, PM 프로필에 임시 시험약을 넣어 확인한 뒤 지우고, 확인되면 나머지 연결자에게 넓힘.
- 환경: 운영 서버. 서버 `428d404`, 다리는 카톡 다리 PR #22를 넣은 판. 받는 사람을 PM 연결 하나로 제한함(`REMINDER_ONLY`).
- 남기지 않은 것: 키, 대화 원문, 사용자 건강정보, 프로필 이름, 운영 로그 원문. 아래 수는 로그의 수만 옮김.

## 08:00에 카톡이 가지 않은 까닭

07:50에 시험 모드를 끄는 일을 작업 세션의 대기 타이머에 맡겼는데, 세션이 끝나며 타이머도 끝남. 그래서 시험 모드로 남았음. 코드 문제는 아니고 운영 절차 문제임. 시험 모드는 설계대로 보내지 않았고, PM "카톡이 오지 않았다"로 드러남. 이후 시각이 정해진 운영 단계는 세션 타이머에 맡기지 않음.

## 확인한 것

- PM 카톡 도착: PM "도착함"(2026-11-05 08:16, 프로젝트 대화).
- 서버 기록상 실제 전송 1건: 카카오 응답 전송 성공 1건.
- 다리를 다시 켜도 같은 약·복용 시각을 다시 보내지 않음.
- 웹 푸시 기록은 복용 시각마다 1건씩이고 카톡 전송과 따로 돎. `MedicationReminderService`는 바꾸지 않음.
- 복약 알림을 보낸 수 1건(`reminder_usage`).

## 확인하지 못한 것

- 웹 푸시가 PM 기기에 뜬 것. 서버의 보낸 기록까지만 확인함.
- 다른 두 연결자에게 보내는 것. 넓힌 뒤 첫 복용 시각에 수로 확인함.
- 전송 거절(401·IP)과 네트워크 오류는 단위 시험으로만 확인함. 운영에서 일부러 만들지 않음.
