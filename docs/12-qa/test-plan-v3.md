# 필받음 v3 QA 테스트 계획

- 범위: v3 1차·2차 웹 흐름(V3-FL-17~23)과 v2 회귀 확인, 3차 카카오 흐름(V3-FL-24~26)은 PM 카카오톡 시연, 4차(V3-FL-27~29)는 아직 만들지 않아 해당 없음.
- 입력: `docs/03-user-flow/user-flow-v3.md`, `docs/04-functional-spec/spec-v3.md`, `docs/06-api/openapi-v3.yaml`, `react-client/design/v3-*.md`
- 역할: 비로그인, 로그인 회원, 다른 회원. 보고서에는 역할만 씀. 테스트 계정은 실행마다 로컬 QA DB에 새로 만들고 버림.
- 도는 방식: `api`는 요청을 직접 보내 응답과 DB 변화를 봄. `agent`는 Aside 브라우저 에이전트가 화면을 걸음. `manual`은 사람이 직접 함.
- 응답 ID는 `METHOD 경로#상태`로 씀(06 단계 규칙). 화면 상태는 `화면ID#상태`로 씀.

## 실행 환경

- QA 서버: 이 PC의 로컬 스택(서버 jar와 화면 모두 `0fee16e`). DB는 버리는 MySQL(`127.0.0.1:3307`, `pill_qa`)에 `01`·`13` 스키마를 깖. 운영 DB는 쓰지 않음.
- 이 PC에는 OpenAI·공공데이터 키를 두지 않음. 키가 필요한 경우(대화로 제안 만들기, 이름 검색 후보, 사진 판독, 실제 답변 단계)는 '막힘'으로 두고, 키가 없을 때의 실패 화면만 확인함.
- 대화 제안 카드는 서버가 저장하는 모양 그대로 QA 데이터로 넣어 확인함(등록 대기·취소용·만료, 일정 대기, 금기 4종 답변). 카드 생성 자체는 막힘으로 셈.
- 운영(`pillbadeum.example.com`)은 바꾸지 않는 확인만 비로그인으로 함.
