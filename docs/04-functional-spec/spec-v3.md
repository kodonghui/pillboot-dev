# 필받음 v3 기능 명세

- 상태: 초안(2026-11-02). 입력은 [v3 요구사항](../02-prd/requirements-v3.md) V3-REQ-33~80, [v3 사용자 흐름](../03-user-flow/user-flow-v3.md) V3-FL-17~29, [도메인 용어집](../01-domain/domain.md) TERM-001~018, 결정 DEC-001~014.
- 기존 영역별 명세(AUTH·PROF·REG·DRUG·SCHED·DOSE·NOTI·CHAT·COMMON·V2-*)는 Notion 기능 원장이 원본이며 여기서 고치지 않음. v3가 바꾸는 기존 행은 7장에 적음(REG-003 포함).
- 코드 사실은 2026-11-02 팀 저장소 `docs/v3-scope-20261102` 브랜치(기준 `9b5b5ef`)에서 확인함. API 경로·테이블 이름은 06 API·05 ERD에서 정하며, 이 문서의 이름은 후보임.
- 수용 기준은 "~이 주어지고, ~하면, ~임" 순서로 씀.

## 8. AI 호출

### 8.1 V3-CHAT-001 질문 의도 가르기

| 항목 | 내용 |
| --- | --- |
| 입력 | PASS로 분류된 질문 글(카카오는 묶은 글), 프로필의 약목록 이름 목록(일정 요청의 대상 약을 고르기 위함) |
| 보내지 않는 것 | 회원 이메일, 프로필 이름·출생연도·키·몸무게, 다른 프로필 정보 |
| 출력 | JSON: `intent`(QUESTION·REGISTER_DRUG·SCHEDULE_CHANGE), `drugMentions`(이름·함량 원문, 최대 10), `targetMyDrugName`(일정 요청일 때) |
| 서버가 확인하는 것 | 값이 정해진 셋 중 하나인지, 이름 길이, 목록 수. 형식이 틀리면 QUESTION으로 처리 |
| 실패 | 오류·시간 초과·한도 → QUESTION으로 처리하고 기존 답변 흐름을 탐(저장 없음) |
| 사람 결정 | 등록·일정 변경은 회원(지인)이 카드·빠른 답장으로 확정해야만 저장됨 |

### 8.2 V3-CHAT-006·V3-KAKAO-004 사진 판독

기존 처방전 사진 판독(REG 영역 AI 호출, `PrescriptionOcrRules`)을 그대로 씀. v3 변경은 판독 뒤 후보 대조(V3-REG-002)와 결과를 등록 제안으로 받는 것뿐임. 사진 속 글자는 데이터로만 다룸.

### 8.3 V3-KAKAO-006 음성 받아쓰기

| 항목 | 내용 |
| --- | --- |
| 입력 | 카카오 음성 파일(형식은 H-01 확인 뒤 정함), 언어 한국어 |
| 보내지 않는 것 | 지인 키·프로필 정보·대화 기록 |
| 출력 | 받아쓴 글 |
| 서버가 확인하는 것 | 길이(1분 이하), 빈 결과. 받아쓴 글을 묶음 글에 합친 1,000자 상한은 다리가 먼저 확인하고(V3-KAKAO-003), 기존 질문 API가 다시 확인함 |
| 실패 | 오류·시간 초과·빈 결과 → 받아쓰지 못했다고 알리고 글로 보내 달라고 안내 |
| 사람 결정 | 받아쓴 글로 만든 제안·일정도 확정 뒤에만 저장됨 |

### 8.4 V3-CHAT-007 일정 해석

기존 단문 일정 해석기(`MedicationVoiceInterpreter`)를 '해석만' 쓰고 저장은 확정 뒤에 함. 입력·출력 형식은 기존 `ParsedCommand`와 같고, 서버의 기본값·권한·업무 검사도 그대로 씀.

## 9. 열린 문제

| 문제 | 영향 행 | 다음 행동 |
| --- | --- | --- |
| H-01 카톡 음성 형식 | V3-KAKAO-006 | 11/4 뒤 실제 음성 1건으로 확인 |
| H-13 묶은 메시지의 콜백 토큰 | V3-KAKAO-003 | 3차 시작 때 시험 |
| 60초를 넘길 때 '확인 중'을 먼저 보낼지 | V3-KAKAO-003 | 콜백이 이벤트마다 한 번이라 보낼 수 없을 수 있음. 시험 뒤 정함 |

- 닫은 문제: H-16(자동 프로필 임신 여부)은 DEC-016으로 답함(2026-11-02). V3-KAKAO-001·002에 반영함.
- 고친 사실: V3-COMMON-003의 '기존 내 약 규칙과 같음'은 틀린 근거였음. 기존 내 약 API는 다른 회원 프로필에 403, 복약 일정 API는 404를 줌. 새 대상은 명세대로 404이고 근거를 복약 일정 API로 고침(2026-11-02, TASK-009).
