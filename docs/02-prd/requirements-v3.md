# 필받음 v3 요구사항

- 상태: 초안(2026-11-02). 범위는 PM 승인(v3 범위 결정 DEC-001~014) 안이며, 도메인 체크포인트 질문 5개는 DEC-010~014로 답함. 문장 검토(범위 고정 체크포인트)는 전임.
- 기존 REQ-01~23·V2-REQ-31~32는 요구사항 DB가 원본이며 여기서 고치지 않음. 바뀌는 기존 행은 7장에 적음.
- 문형: EARS 다섯 가지(항상 · ~하면 · ~하는 동안 · ~이면 그때 · ~가 있는 경우) 중 하나와 "해야 함" 하나만 씀.
- 우선순위: Must(이 차수에 꼭) · Should(이 차수 목표, 밀리면 다음 차수) · Could(여유가 있을 때).
- 차수: DEC-007 순서. 1차 사용성·함량 → 2차 웹 대화 등록 → 3차 카카오(11/4 이후) → 4차 진료 일정.

## 8. 점검 결과

- 모든 행이 EARS 한 문형과 "해야 함" 하나를 씀. V3-REQ-63은 측정 조건(지인 3명 이하, 운영 서버 다리 로그, P95 60초)을 적음.
- 모든 행에 유형·우선·CTX·출처가 있음. 우선순위가 정해지지 않은 행은 V3-REQ-81~84뿐이며 PM 결정(Q5)을 기다림.
- 중복·충돌 점검: V3-REQ-52와 V3-REQ-61은 같은 규칙을 웹·카카오 경로에 각각 적용한 것이라 중복이 아님. V3-REQ-47·48·49는 저장 조건·확정 전 금지·재확정을 나눈 것임.
- 용어: 함량·기본 이름·등록 제안·제안 확정·진료 일정·동행자·사전 알림·캘린더 링크·카카오 지인·메시지 묶음·여러 개 삭제·약목록 약·공식 약을 용어집(TERM-001~018)대로 씀. CTX 번호는 팀 보드에 맞춘 도메인 설계(CTX-001~008)를 따름.
- 확인 대기 행: V3-REQ-59(카톡 음성 형식, 11/4 뒤 실제 1건으로 확인). V3-REQ-55·78은 DEC-011·012로 답함.
- 2026-11-02 19시 무렵 DEC-021로 V3-REQ-80을 더함. 1차 V3-REQ-43(화면이 아는 단계만)을 답변에서는 서버 단계로 넓히는 것이라 충돌하지 않음.
- 기능 명세를 쓰며 고친 것(2026-11-02): V3-REQ-52·61은 '기존 단문 일정 명령의 확인 단계'라고 적었으나 기존 명령은 확인 없이 저장함(`MedicationVoiceScheduleController` 설명, 코드 확인). 확인 카드로 확정받은 뒤 저장하는 문장으로 고침. 운영자 연결 해제·삭제 동작에 요구사항이 없어 V3-REQ-79를 더함.
- 못 본 것: 기존 Notion 행의 '수용 기준' 칸 다수가 비어 있어 기존 REQ와의 세부 충돌은 동작 칸 기준으로만 비교함.
- 2026-11-04 PM 요청("이거 채팅에서 낱알가지고는 검색못하나? 홈페이지랑 카톡에서")으로 V3-REQ-81~84를 더함. 사진 종류를 가르는 방법(Q1)·장수와 카톡 두 장 모으기(Q2)·결과 카드(Q3)·못 찾았을 때 문구(Q4)·차수와 우선(Q5)은 PM이 정하기 전이라 상태는 '결정 대기', 우선은 '미정'임. Q1~Q5의 안과 장단점은 [기능 명세](../04-functional-spec/spec-v3.md) 9.1에 있음.
